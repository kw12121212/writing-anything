5. 真实注册表取证（评审修复后追加，2026-10-20）【rank 50 内置胜出的表述已被第 6 节取代】：
   初版 provider 的 list/get 是同步的——插件自身状态显示 registered:true，但每个真实消费方都带
   AbortSignal 调用，注册表 waitWithAbort 对返回值直接调 .then，同步数组导致整个 provider 被跳过，
   宿主技能清单里一个 wa-* 都不会出现（全新上下文评审发现；插件自身路由的状态字段正是盲区）。
   修复为异步契约 + 候选补 locator 字段后，用真实宿主包取证（/tmp/skill-registry-evidence.mjs，
   import 真实 @deepseek-ai/dsh-skill 的 SkillRegistry 与 cordis，注册本插件导出的
   registerSetupSkills provider，另注册一个 rank 200 的同名竞争 provider）：
   - `registry.list({ signal })`（带 AbortSignal 的真实调用路径）→
     catalog: wa-auto@dsh-writing-viewer, wa-init@dsh-writing-viewer（竞争方的 wa-init 未入清单）
   - `registry.get('wa-init', { signal })` → 'BUILTIN INIT BODY'（内置正文，非竞争方正文）
   - REAL-REGISTRY-OK：异步契约在 signal 路径下成立，同名时 rank 50 的内置版本胜出。
   单元测试同步加了契约回归网：fakeSkills 按 waitWithAbort 语义（带 signal、要求 thenable）驱动
   provider，同步返回会直接测试失败。
